# Git ワークフロー規約

## コミット前チェック

- 機密情報（APIキー・パスワード・`.env`ファイル）がステージングされているか？ → **Yes**: コミット対象から除外する
- `git add .` / `git add -A` を使おうとしているか？ → **Yes**: ファイルを個別に指定する（意図しないファイルのコミット防止）

## コミットメッセージ

- コミットメッセージが変更の「理由」を含んでいるか？ → **No**: 「何を」だけでなく「なぜ」を記載する
- 言語: **英語**（既存履歴に合わせる）
- 形式: 命令形で始める（`Add` / `Fix` / `Move` / `Update` / `Remove` など）
- 末尾にピリオドなし、60文字以内
- 例: `Add file map to CLAUDE.md for faster navigation`

## ブランチ戦略

- 3ステップ以上の変更か？ → **Yes**: 専用ブランチを切り、PR経由でマージする
- 緊急の本番バグ修正か？ → **Yes**: `hotfix/` プレフィックスで作業ブランチを作成する

## 破壊的操作の確認

- `git reset --hard` / `git push --force` / `git branch -D` を実行しようとしているか？ → **Yes**: ユーザーに確認を取ってから実行する
- `--no-verify` でフックをスキップしようとしているか？ → **Yes**: 根本原因を調査・修正してから実行する。スキップはユーザーの明示的な許可がある場合のみ
