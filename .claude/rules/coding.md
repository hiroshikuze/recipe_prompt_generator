# コーディング規約

## 多言語対応（i18n）

- `index.html` または `main.js` のUIテキスト（console出力を除く）を変更・追加したか？ → **Yes**: `locales/ja.json` と `locales/en.json` を同時更新する
- 新しいテキストキーか？ → **Yes**: 一意のキーを割り当て、`data-i18n` 属性を使用する形式で実装する

## JavaScript 基本構造

- `.js` ファイルか？ → **Yes**: 先頭1行目に `"use strict";` を記述する
- 変数宣言に `var` を使っているか？ → **Yes**: `const` / `let` に置き換える
- アロー関数に書き換えられる通常の関数か？ → **Yes**: アロー関数を使う
- 関数の行数が50行を超えているか？ → **Yes**: 責務ごとに関数を分割する

## 命名規則

- 変数・関数名がキャメルケース（camelCase）でないか？ → **Yes**: 修正する
  - 例: `user_name` → `userName`、`GetData` → `getData`

## インデント

- インデントがスペース4文字でないか？ → **Yes**: スペース4文字に統一する

## パフォーマンス

- ループ内で DOM の `querySelector` / `getElementById` を繰り返し呼んでいるか？ → **Yes**: ループ外で一度取得し変数に格納する

## エラーハンドリング

- 外部リソースアクセス・API呼び出しがあるか？ → **Yes**: `try-catch` でラップし `console.error()` でエラーを記録する

## セキュリティ

- APIキー・パスワード・シークレットをクライアントサイドのコードに含めているか？ → **Yes**: 静的サイトのためクライアントに秘密情報を置かない。外部APIが必要な場合はサーバーサイドプロキシを経由する

## ログ出力

- 複雑な処理フローがあるか？ → **Yes**: `console.log()` で処理の流れを追跡できるログを追加する

## コメント

- 関数が存在するか？ → **Yes**: JSDoc形式のコメントを付与する（`@param` と `@return` の型定義を明記）
- 複雑なロジックがあるか？ → **Yes**: 日本語で目的・理由をコメント追加する
- 自明な1行コード（`i++` など）か？ → **Yes**: コメント不要

## モジュール・インポート順序

- インポートの順序が「外部ライブラリ → 内部モジュール → 型定義」でないか？ → **Yes**: この順序に整列する
